Vectors and system versioning in one table
  a VECTOR INDEX on a system-versioned table can be created                  yes
  history rows with vectors can be written with their own dates              yes (system_versioning_insert_history)
  the nearest rows AS OF 2015 are the ones that were nearest in 2015         yes
  ... and that search uses the vector index                                  yes
  a vector handed over by a scalar subquery still uses the index             yes
  an UPDATE keeps the old vector as a history row                            3 versions of row 7
  a versioned table with a VECTOR INDEX can be PARTITIONed BY SYSTEM_TIME    no: Partitioned tables do not support VECTOR
